# 18 Slicer Handoff Generator Notes

Date: 2026-06-11

## Summary

Phase 4 handoff generation is implemented in the backend, without launching
Slicer and without making Slicer visual alignment a blocker.

The runner now generates:

```text
out/slicer/open_in_slicer.py
out/slicer/label_names.json
out/slicer/label_colors.json
out/logs/mask_stats.json
out/README_OUTPUT.md
```

## Scope

Implemented:

```text
- Generate a self-contained Slicer Python script.
- Load the source volume from the copied case input when present.
- If --no-copy-input is used, reference the original input path from the script.
- Load every generated .nii.gz mask under segmentations/ as a Slicer labelmap.
- Prefer `teeth_multilabel_fullspace.nii.gz` and skip
  `teeth_multilabel_roi.nii.gz` when both are present.
- Set labelmap node names from label_names.json.
- Set simple display colors from label_colors.json when possible.
- Count nonzero voxels for readable NIfTI masks and write logs/mask_stats.json.
- Write README_OUTPUT.md with run status, paths, masks, and non-clinical notice.
```

Not implemented:

```text
- Launch Slicer from the backend.
- Validate visual alignment in Slicer.
- Convert labelmaps to Slicer Segmentation nodes automatically.
- Export STL files.
```

## Label Map Behavior

The v0.1 script intentionally loads raw TotalSegmentator outputs as labelmaps.
This is conservative and easier to inspect/debug than attempting automatic
conversion to a Slicer Segmentation node before visual validation.

Current label names:

```text
head -> Head
mandible -> Mandible
sinus_frontal -> Frontal sinus
sinus_maxillary -> Maxillary sinus
skull -> Skull
teeth_multilabel -> Individual teeth experimental multilabel
teeth_multilabel_fullspace -> Individual teeth experimental multilabel
teeth_multilabel_roi -> Individual teeth experimental multilabel ROI
teeth_lower -> Lower teeth
teeth_upper -> Upper teeth
```
